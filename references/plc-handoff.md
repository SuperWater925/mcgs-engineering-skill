# 逐段PLC合同与离线验收

当前方案是“执行监视与单段请求/PLC单段v3_精简”，2026-10-23已合并进主线PLC与HMI。v2和分块v1为历史，不拿旧方案的长度、地址或报告套当前文件。接手先从当前原厂公开符号XML、当前PLC工程、当前MCS和实际源码重取SHA；历史报告对应的hash可能已因用户保存变化。

## 精简v3合同（当前）

完整定义在`PLC单段v3_精简/通信变量表与握手.md`，合并记录在`20261023_测试版合并主线_110429/合并实施与联调说明.md`。

- 20个平铺变量，前缀`Application.单段通信表.`。前12个触摸屏写（下发段号、总段数、目标温度/压力、持续秒、切段条件、比较方式、容差、真空开关/目标、下发标记、起始段号），后8个PLC写（请求段号、请求序号、执行状态、当前段号、已完成段数、本段已用秒、故障码、心跳）。
- 握手：
  1. PLC置`请求段号 = k`，`请求序号`加1。
  2. 触摸屏用一条Write写第k段10个参数，成功后再写`下发标记 = 请求序号`；任一条失败，下一周期整段重写。
  3. PLC看到标记和段号都匹配才取用；参数越界报故障码2。
- 没有应答头、校验和、双读回读；靠命令成功返回和“参数先写、标记最后写”的顺序保证整段一致。
- 功能块`单段保压执行`用一个CASE状态机和TON：空闲、等待段、运行、暂停、完成、中止、故障。等段超时默认5秒，故障码1。只输出状态位，不出脉冲。
- 主线接入：Main在传感器调用之后、设备调用之前调用`保压工艺调用`。整机流程第60步启动整套段工艺，等`工艺完成`后才跳第70步。温度、压力、真空设定还没接实体控制回路。

## EVOs FreeTag驱动与iFA实测

- 驱动走CIP，连PLC的TCP 44818。汇川PLCSim要在iFA硬件配置LAN1下加EtherNet/IP Adapter才开44818。
- 设备命令类型码按驱动实际实现写：BOOL 90、SINT 91、INT 92、DINT 94、REAL 95、WORD 105。帮助文件写的93=DINT、94=REAL是错的，驱动里92、93都映射到INT。
  - 类型码写错时，读正常（按回包类型解码）；写会悄悄失败：命令返回0，PLC收不到，也不报错。
  - 改命令后对照最终PLC类型逐条核对，不要改回早期测试工程里的类型码。
- ReadArr/WriteArr的“连续变量”按起始变量名末尾两位阿拉伯数字递增（`%s%02d`）。中文数字编号只会填第一个，所以连续对象要命名为`xx00…xx33`。
- iFA新建的枚举默认带`qualified_only`，ST里枚举值要带类型名，如`单段保压状态.运行`，否则编译报“没有定义标识符”。
- 打开着的iFA在127.0.0.1:9000提供OpenApi（第二个实例为9001），可建工程、导入对象、编译、导出ST与读模块信息。项目工具在`PLC单段v3_精简/iFA接口工具/`，有通用的`methods`与`call <方法> <json>`。
  - `import-objects`会删掉清单里没有的程序对象并清空注释，要一次给全，再逐个`import`写回注释和公开属性。
- 仿真下载后的公开符号在`C:\Inovance\iFA Evolution\Bin\PLCSim\app_0\Symbols.xml`，可转成HMI设备0导入用的XML。
- 只读核对PLC值用`PLC单段v3_精简/只读读取PLC变量.py <IP> <变量…>`（CIP Read Tag），它不写。离线编辑授权不含下载或RUN。

## v2单段合同（历史）

HMI冻结准备发送的工艺，PLC按段请求。HMI校验会话、批次、段号/总数、请求和提交标记，写34WORD，再独立回读完整34WORD并检查；PLC确认后才可推进。ACK完整读20WORD，执行状态完整读48WORD。不得拿启动请求写成功当作PLC接受工艺，更不能把本地变量变化当设备动作成功。

真实公开标签的本项目映射：

| HMI标签字符串对象 | PLC公开变量（Application.单段通信表.前缀） | 权限/长度 |
| --- | --- | --- |
| 单段写入请求标签 | 人机写入请求 | WORD，读写 |
| 单段提交标记标签 | 人机提交标记 | WORD，读写 |
| 单段接收数组标签 | 人机接收字 | WORD[0..33]，读写 |
| 单段状态请求标签 | 人机状态快照请求 | WORD，读写 |
| 单段写入确认标签 | 控制器写入确认 | WORD，只读 |
| 单段应答标记标签 | 控制器应答标记 | WORD，只读 |
| 单段应答结果标签 | 控制器应答结果 | WORD，只读 |
| 单段应答数组标签 | 控制器应答头 | WORD[0..19]，只读 |
| 单段状态数组标签 | 控制器状态快照字 | WORD[0..47]，只读 |

标签完整形式例：`Application.单段通信表.人机接收字`，数组标签名不加`[0]`；ReadArr/WriteArr已有起始下标0参数。本地对应整数对象必须从ObjData逐ID复读，确保连续34/20/48个且类型匹配；不得凭猜测或名字顺序确定。实际命令名称与数组下标/长度按当前EVO驱动帮助和公开符号核对。

另有只读DINT“控制器心跳/控制器状态发布序号”，当前由48WORD完整冻结状态快照取得，不能绕一致性规则直接回读某个已发布字段。

## v2一致性与恢复（历史）

状态快照需要新token/完整双读一致性与新鲜度。确认/回读超时、错session/批次/段号、内容不符或链路过期时撤销高亮并保留占用，避免把旧状态标为正在执行。停止HMI供数不等于PLC停机。

PLC末段不请求N+1；等待下一段时保持上一段已采用温压/真空，不新增泄压或运动动作。当前WAIT默认5秒可配，超时故障优先，迟到数据不得复活已结束流程。断链同会话恢复不能自动续发，需真实复位与人工确认；首次观察session只作基准。非保持session无法严格识别采样间完全不可见且计数恰相同的快速重启，不宣称覆盖该边界。

HMI总段数守卫与PLC最大总数10082配套；字段打包、校验、WORD低高字顺序、负值/浮点解释按实际v2源码，不臆造地址。修改容量或段负载时同时审查HMI、PLC、公开符号、连续对象与回读合同。

## 验收区分

已有纯源码联动模型覆盖延迟、超时、回读不符、批次/会话与末段，属于离线源码执行测试。PLC原厂编译、Mcgs原厂编译、本机Mcgs+虚拟PLC实联和实体设备结果必须分别记录。模型中的PLC20ms/HMI100ms/命令40ms只是测试调度，不是现场实时承诺。

模拟前隔离旧工程设备自动轮询端点；新供数门控0不等于旧通道停止。虚拟PLC地址、端口、SN等从实际仿真配置读取，不猜loopback固定值。离线编辑不授权现场下载或设备写入。
