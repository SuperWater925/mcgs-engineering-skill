# Pro 跨构建适配

软件大版本、小版本和作者厂商整文件 SHA 不作准入白名单。当前实现按选定程序的真实接口生成调用资料；不得将某个函数缺口解释为必须升级到离线模板的来源版本。

## 地址、模块与校验资料

- 参考目录包含控件虚表槽、稀疏表、方法表、分支目标、引用编码的 VA、IAT 和导出角色。字段可能是数组或使用历史别名，不能只扫描 `_rva` 标量；槽索引、对象字段和业务数值不改成地址。
- 导入函数按实际符号角色核对。命名导入的 Hint 仅为查找提示；序号导入仍须由当前已定位目标和实际导出证明，不能简单忽略序号。证明冲突撤销时，依赖它才定位的函数也要重新判断。
- HIGHLOW 重定位与检查片段末尾相交时，只调整片段内已有字节，保留相应偏移，不能丢掉部分字节或扩大原生内存读取。运行时继续逐字节比较实际代码。
- 模块的映像大小来自本次 PE；对象大小、字段偏移、继承和调用方式仍按真实结构合同处理。代码 guard 规范到参考 preferred base，其含义不能与当前模块身份元数据混用。
- 模块选择优先显式映射和实际 EXE / 导入依赖关联；参考安装相对路径只作后备。发现可选模块不可读、架构不符或歧义时，记录相应模块不可用，不能拖垮无关功能，也不能复制旧厂商 DLL 冒充适配。

生产绑定可重复给出 `--actual-module alias=绝对文件路径`，例如已确定实际 DLL 路径后传入 `--actual-module "mfc=$ActualMfcDll"`。别名沿用目录的逻辑名，真实文件名、路径及模块身份按本次资料记录。显式 editor 与业务 scope 的目标保持一致。

## 按需解析与原生资源

工程身份通过最小根文档 getter、实际类型及路径读取，独立于策略、复制和保存能力。控件、策略、模板等仅在本次操作实际需要时解析函数及表；未使用条目的缺口不会单独阻止其它功能。

部分 profile 仅由具名的 lazy reader 读取。绑定索引声明 `mcgs-native-lazy-entry/v1`，读取时仍核真实文件 SHA；调用前核对应条目、代码、模块和对象。普通文件读取不能借此绕过整个资料未适配的状态。临时原生资源的构造、赋值和释放等实际所需接口在资源创建前一起解析，避免中途才发现清理接口缺失。

方法或导出映射容器仍保留原值类型与枚举含义，不能插入会被当成函数的额外键；条目状态标在具名行，或放到单独的索引。

## 更新与多安装

技能更新后，已加载的旧业务引擎仍是旧代码。用[已有桥更新入口](pro-native-deployment.md#已有桥的同任务更新)选择新 DLL 和 scope，复用实际连接；不要再次首次 stage、覆盖已加载 DLL、清除 claim 或强制重启 Pro。

回执的 `cross_build_contract` 是工具修订记录，不是 Mcgs 软件版本白名单，也不按精确修订号拒绝未来工具。检查本次所需接口的条目验证能力；旧引擎缺少该能力时更新引擎，不能从“已经动态定位”推断所有消费分支都具备新版实现。

默认热接按目标实际路径接入。可选冷接的自有 COM / TYPELIB / wrapper 身份按部署实例生成，安装、移除和启动按本次 EXE 完整路径判断；旧已部署配置按其实际记录处理，不因复制技能修改本机注册表。

## 离线与实际边界

PowerShell 导出、Python 审计、界面工具和 Pro JSON 编辑共用同一份产品家族规则。大小写、分隔符和 BOM 不构成另一发行版；MCGSVER 原文字节继续保留，归档结构另行核对。

当前原生指针和调用合同仍为 x86 / MSVC。真实对象字段、槽顺序、类层级、编码或归档结构变化，需要对应适配，不能通过删除比较声称兼容。Windows、PowerShell、Python、ACE 和自有桥编译依赖属于工具环境，不是 Mcgs 版本准入。

文件定位、派生资料编译、连接、原厂编辑、保存、文件回读、检查、重开及模拟分别记录。当前消费链规则见[逐项处理](compatibility-resolution.md)，本轮结果见[分项证据](compatibility-resolution-validation.json)；[适配补全](compatibility-completion-validation.json)和[九项修复验证](cross-build-fixes-validation.json)保留此前发布版范围，未执行项不得写成通过。
