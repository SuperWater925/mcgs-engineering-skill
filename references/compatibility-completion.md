# 跨构建适配消费链

本页记录前轮v3消费链实现，软件发行号不参与准入。当前逐项处理和真实边界见[后续复查处理](compatibility-resolution.md)。`cross_build_contract`用于识别工具修订，不按精确值拒绝未来工具；按实际所需能力通过`native-engine-select`更新业务引擎，不清除请求或复制旧会话资料。

## 在线局部操作

代码守卫统一按实际可见字节处理 HIGHLOW；片段长度及精确比较保留。模块文件与句柄使用绑定索引里的实际完整路径，逻辑模块键继续保留。不能重新用 ProgramRoot 拼参考目录，或只按同名 DLL 猜实际所有者。

变量和配方分别按当前操作解析；分配原生资源前解析实际需要的释放接口。调用方在锁定准备状态前，准备它将使用的对象、管理列表、逻辑记录和保存参与者，不因无关模块差异全量预热。管理列表按真实容器与唯一类型识别，不要求恰好五项或某一固定位置。

同页未知、未定位的非目标 CDraw 可以保留已证明的公共身份与原生顺序，局部已知目标及原生新建可继续。未知对象的私有字段不会被解释为已验证；若目标位于未知组内，或操作需要未知生命周期、完整私有 payload/整页结构，则明确报告对应缺口。不能伪造类型、删除对象或将公共头比较称作完整序列化验收。

RTTI/COL/层级唯一证明可独立确定主表身份。当前表少了参考尾槽时，仍记录共享槽及缺失槽；只有当前存在的槽提供函数锚点，实际调用继续核所需槽和布局。表身份不是所有参考方法都存在的证明。

## 离线局部操作

Pro JSON 和 Stu 审计采用相同的明文/MCGSZIPE 包络处理。未修改内容保留原压缩字节；修改后保留原封套类型。双长度、压缩校验、尾耗尽与回环检查继续执行。

只在操作需要时解析目标页、明确模板页和变量绑定。未修改的其他页面、未知记录和设置尾部保留原字节；新增窗口以实际 WndUser 名称列检查重名，不为读名称遍历全部窗口归档。共享新增事务从当前 schema 选择 strNote 或 strComment，模板附加列不重建。

窗口属性按已证明的字段位置及 Variant 类型修改，保留追加属性、密码不透明数据及事件尾。集合数量按实际剩余流和 wire 字段容量检查，不因样本数量拒绝工程。未知 Variant、变量/插件/动画布局仍需实现对应 codec。

## 可选冷接协议

默认热接不使用这些冷接设置。冷接准备从实际 loader capability 的 `capabilities` 读取：

```json
{
  "addins_ini_preload_section": "LoadPlugins",
  "addins_ini_encoding": "auto",
  "addins_ini_no_bom_encoding": "windows-1252",
  "startup": {
    "value_name": "BootCycle",
    "accepted_values": [7, 9],
    "scan_value": 5
  }
}
```

这些值只是配置示例，不能当成任何工程的真实值。应从当前程序的实际加载协议取得。auto 按 BOM 识别 UTF-8/UTF-16；无 BOM 使用明确声明的编码，不用 ASCII 文件猜测将来插入文字的编码。原 INI 必须按选定编码原样回环，节名按不区分大小写匹配，原行与换行保留。旧配置沿用既有字段默认以维持部署兼容；新配置可指定实际节、键名、状态和扫描值。

当前在线仍为 x86/MSVC；实际对象布局、调用约定、指令证明与归档结构变化需要对应适配。地址动态定位、文件回读、原厂检查、关闭重开及模拟分别记证据，见[本轮分项记录](compatibility-completion-validation.json)。
