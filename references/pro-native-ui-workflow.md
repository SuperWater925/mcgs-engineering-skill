# Pro 在线界面施工

本页用于已打开 Pro 工程的布局与样式增量组态。Stu 与明确离线任务仍走字节归档流程。软件版本只记录；运行能力由当前 `compiled_kinds`、实际 getter 声明、二进制/RTTI/布局守卫和产品能力共同决定。内部接口不是原厂公开 SDK。

## 写入前先激活并核实目标窗口

“最前”指 Pro 内部正在操作的页面或编辑器处于活动状态，**不是 Pro 必须成为 Windows 全局前台窗口**。首次施工及切换页面、策略或数据库组态目标时，先通过已有内部入口打开并激活目标，再核对当前工程、目标身份和软件内部活动界面，之后连续写入。创建对象前显示其所属编辑界面，不能修改到一半才切过去。

对目标画面执行一次 direct `page-view-open`，核对回执中的 `exact_page_is_active` 及目标工程、页面身份。调用会核对原生 frame、所属进程、文档和 MDI 活动 child；若 `already_active=true`，沿用当前画面。`open=true` 或 frame 存在仍须结合实际活动页判断。任务要求单独保留视图证据时可再读视图。窗口标题的原厂未保存星号不改变目标身份。

不检查或争抢 Windows 全局 foreground，不强制主窗口或页面最大化，不因参考图片、聊天窗口获得系统焦点而暂停、重建 session 或要求用户重新确认。只有用户另外明确要求把软件置于系统前台时，才按该请求处理。使用内部接口不以电脑操作技能为前置条件；用户禁止该技能时不得调用。

已有授权下按整页程序连续实施；内部切页不增加逐批审批。用户明确要求等录屏后开始时，仍先准备完整程序并等待那一次开始确认。纯文件准备不冒充原厂界面施工。

## 先完成方案，再实施

先取得当前页面、完整父子森林、typed properties、动画/事件与引用前像，按实际 page ID、complete、owner、class/name 和完整 path 映射。同页可能重名，不能只按名称选控件。层次变化后按新回执重建 path；不要给所有旧索引机械加常量。新装饰尽量 append，底板集中置底，减少反复移动原业务对象。

一次准备目标页全部几何、样式、图片、单位、装饰及保存范围；按用户已有授权实施。只有用户明确要求“方案全部准备后通知、等开始”时才先只 stage，不能将这一偏好变成所有任务的新确认流程。保留范围外页面及原功能；公共窗口影响所有引用它的页面，需从当前引用而非截图判断。截图的文字/数字不证明变量含义、单位、0/1状态或运行结果；由当前工程及用户说明确认，不能把某工程的“0本地/1远程”写成通用常量。

施工优先复用现有接口，不在写工程过程中顺手研发 SDK。缺功能时先保持原业务并列精确缺口；必要扩展在纯文件准备阶段完成。同页连续原生创建现可在direct中共用一次历史和末尾刷新，逐项构造与核对保留；兼容step自动合并RPC、依赖及保存边界见[在线提速合同](pro-native-performance.md)。这不代表任意跨页/派生控件都支持通用批量创建，新批次的原厂运行验收范围见相应记录。已有几何/属性批次继续复用。

## 几何与样式批次

- `control-geometry-batch` 每页接受非空的不同控件集合，不再按样本写死64项；目标含当前完整 path/name/class，仍拒绝同批父子、祖孙或重复子树。组使用已证的归一化子矩形合同，核完整森林，不能只验证外框。当前入口要求原绘图 view 已存在，原 page property13 满足其前置守卫；按实际 Read/Prepare 拒绝结果处理，不暗改该字段。实际消息容量仍须满足。
- `control-properties-batch` 同样不再写死64个 full control；同一 full 的 root、抬起/按下或多个状态组件分到不同批。每次采集共用同页上下文，并在各核对点重新读取。只写确实变化的、由 getter 声明的 native_key/tag/value。不能按 collector slot 猜数据类型，不能用整个控件可写来推断所有嵌套成员都可写。
- 字体保留原 `native_flag`、全部 language rows 和原 language ID；大小、字重及字体面按明确设计调整。动态文字按最长真实值、负号、小数位、状态文本和单位留宽，不用“12.3”或空预览证明不会裁切。
- 颜色低24位为 BGR。普通颜色修改保留原高字节；原 common FillColor/BorderColor 的高字节是独立 enable 整数，不是可随意清位的 flags。仅在已证 common 字段上，禁用用高字节整体0、启用实心用01，并保留或明确设置RGB。字符颜色的FF等高字节不能据此改成 enable。Label 需要露出白卡时关闭其真实 common 填充/边线门控，不改可见/使能/安全表达式。

### Flow 与原厂包络

`CDrawFlow` 的原几何 setter 根据中心线、管道粗细和外线宽重建包络，输入 RECT 不保证原样返回。本轮8高输入得到13高是该对象的包络结果，**不是全类最小高度13**。布局先保持真实管厚并按已证平移/包络规则安排；未闭合缩放不猜。若原 setter 返回不同包络，保存请求与实际前缀结果，读回完整森林后只生成未执行尾部；不能把更宽的几何比较容差当修复。

### 标准按钮的两态共享样式

标准按钮的 BasicPropertyProxy 与 OperationPropertyProxy 可以使用相同中文状态 key；必须核真实 RTTI、原 owner、component_path 和 occurrence。当前已证 BasicProxy 为 `抬起状态/0`、`按下状态/0`，不能误选动作代理。

修改 BasicProxy 的**字体、字符颜色、填充颜色、边线颜色、显示文本**时，在 batch item 显式带 `expect_paired_basic_button_visuals` 布尔字段。先用带字段的 Read 取得 `paired_basic_button_visuals`，Prepare 将声明值绑定为实际条件，不省略合同等失败后再猜副作用；当前 ABI 的原规则为 `Button+0x394.GetAt(1)==1`，不改原条件数组。true 时仅把本次请求的这五项预期同步到同一按钮另一真实 BasicProxy；false 时不扩配对预期。其它字段及 OperationProxy 拒绝此例外。

共享为真时，写按下外观或显示文字可能反写抬起对应属性。若设计以正常抬起态为准，可一次写抬起并把另一态四项相同的原厂效果列入预期，省去随后反写按下态；不要清原共享条件强行制造独立两态。原 BasicProxy 内部0/1构造状态不代表工程里的本地/远程变量值。安全条件、按下/释放动作、使能、日志和绑定始终按原值保全。

### 动态单位拆分

在当前 getter 中定位 `CAniOutput` 的真实 IPropertyLinker，核其单位为 tag8；本轮已证路径为 `动画属性/0`，其它控件仍按实际 key/occurrence 查找，不硬套。

通过该组件原 SetProperties 仅将单位置空，保持输出表达式、数值格式/精度、范围、开关文本及未请求的字段。无需克隆/Serialize 整个动画。原 setter 会同步 Label 内部单位包装（当前 ABI 为 owner+0x168、CString+0x16C）；它与 root `显示文本`（+0xE4）不同，这是精确原厂副作用，不能用 raw CString 或写内存替代。

同时按实际单位新建小字号静态 Label，并给数值 RECT 留出独立单位区域，避免运行时重复单位。字号由分辨率和设计决定，不把本轮13px变成通用值。预览若为“原数字+尾单位”，只去尾单位保原数字；空、中文或非数值预览保持，需另换占位文字时明确只改设计预览，不写变量。原预览尾单位可能与真实组态单位不一致，新单位以实际 `单位` getter 为准。原有单位本来就独立时不重复创建。

### Cell 派生 getter

部分已证 `CDrawCell` getter 由子对象聚合样式，而非直接读父字段。只有原类/聚合函数、精确子列表、批准的子项值和所有权都已证明时，才能由相同子项填充推导父 owner 下的一个 `填充颜色` key；其它值仍严格比较。不能给所有组、所有字段自动放宽，也不能从实际差值倒造 expected，或据 getter 变化断言父 raw 字节改变/不变。

## 新增原生外观接口

- `control-slider-fill-visual`：只设置填充区域的低24位BGR颜色，保留原填充启用高字节、字体、表达式和数值格式；灰色槽体等独立装饰按布局处理。
- `control-mulbutton-visual`：按当前真实状态索引和阈值修改原多态按钮的平面填充，或移除该状态自有图片框。`type=65538` 是平面填充，`type=2` 不填充，`type=0` 仍可能绘制原3D默认底色。移除状态图片不删除图库资源；保留输入/输出绑定、权限、动作、阈值和文字。
- 多态按钮的历史后验实现曾将页面属性数组index13误当 `doc+0x28C`；正确索引为9。修正只改预期投影，index13保持前像，不写原页面条件。

普通 Label 的单位框需容纳原生文字边距；实际案例中的14px宽V/A、20px宽Hz有裁切。不能用单个GDI字宽或截图占位值保证原厂显示，集中做一次实际视觉核对即可，不逐控件反复打开工程。

新增图元的可见/颜色动画优先用已实现的 `new_class` 原生工厂，复制真实源定义的可编辑字段；原厂构造后的完整已知值在加入工程前必须与本次期望一致。已有源动画 `CByteArray+0x14` 可含编译缓存，而原生Serialize/Deserialize克隆可能清空它；现有精确克隆入口对此仍会拒绝，不通过删除原条件或通用忽略字节数组来绕过。不要把一个可见动画工厂实例成功说成全动画类型均已验证。用户明确暂缓新增动画时，先完成静态外观，保留已有动画并如实列出未完成部分。

## 图库与存储比较

新增资源使用顶层 `source.file` 与实际文件 SHA，保留原资源。图片替换只指向精确原状态的图片组件；保留变量、状态阈值、动作和其它状态图片。同名、同像素或同hash均不能代替 owner/path 选择。

保存后逐原资源核 name、索引/顺序、模式、尺寸、draw tree 和完整 payload SHA，新资源单列。原厂重算的 hash/缓存元数据仅在原算法、目标记录、准确字段/offset 与相同 payload 已证明时列精确差异；不统一忽略图片hash、名称或整个元数据块。独立图库 named Bitmap 原 STORE 展开成内嵌像素的合同见[部署与保存](pro-native-deployment.md)，不能声称重开后仍有永久名称链接。

窗口密码默认逐字节保留。有且仅在匹配原 ABI、与原合同一致的 gate（本轮为2）、原 CString 长度0及空串摘要、wire 长度2且首字节 ANSI NUL、精确前后block SHA/差异offset都已证明时，可记录仅第二字节的空ANSI尾字节变化。原 STORE 按 UTF16长度算 `2L+2`，转换ANSI后仍复制该长度；空串只需第一个NUL，第二复制字节不属于字符。SetSize 的目标数组本身先zero，不能猜为随机或归咎未初始化目标。不得套成通用padding mask，不接纳非空密码、其它长度、其它offset或其它ABI；不输出密码文本。

### 纯文件比较入口

使用[规则合同与输入 schema](pro-native-ui-rules.json)和[纯文件检查器](../scripts/native_ui_rules.py)，比较已提取的图库、空密码和 Cell 证据：

```powershell
python -B scripts/native_ui_rules.py --input extracted-evidence.json --out NEW-report.json
```

可用 `--rules` 指定规则文件。输入是已提取 JSON/安全导出数据，不是工程或数据库；输出必须为新文件。`native_profile` 声明须来自独立核实的原生 ABI 捕获，工具只匹配声明，不自证捕获来源。退出码0/2/3/1分别为所提供项目 PASS、DIFFERENCE、REVIEW、输入/I/O错误；缺原生保存凭据的未知 hash 变化保留 REVIEW。该结果不代替原厂检查、原生回读或关闭重开验收。

## 部分结果、集中保存与最终验收

`commit=false` 仅控制 bridge 显式保存，原厂自身保存/计时保存/编译转换仍可能改变 storage。磁盘SHA漂移先保留旧请求与 claim，取新只读事实；只在全部差异已闭合为原厂边界、业务语义与当前批准期望精确一致时，使用新ID和新事实继续未执行部分，direct 在调用中取得当前前像，无需新 permit 文件。不能自动hash rebase、删claim或重发原请求；timeout须先确认原请求状态。

最终一次收尾：同步必要引用（包括完整 expected edges）→以当前事实 direct 保存各页/模块→单独一次 RootSave→必要的一次原 Root85→保存检查后的统一只读 typed/forest/graph及业务比较。已有策略私有工作文档先用真正 pure-sync/close，历史 Doc83 可能内嵌全RootSave，不能叫child-only。不要为每个小步骤导出、保存、关闭重开或重跑全部功能；需要持久重载验收时再集中一次正常 Close/Open。

相邻、范围明确且彼此没有回执依赖的 `page-flush` 与 `root-flush` 可交由 `run` 合并为一次 RPC。仍按顺序执行各页原生保存和一次 RootSave，并分别核对各动作结果。结果不明时先核对原请求和实际工程状态。

Root85 的 `ok=true` 只说明调用正常返回。通过须同时满足 `native_check_passed=true`、`original_worker_call_entered=true`、`original_worker_returned=true`、`original_worker_return_int32==0` 和 `state_after.root_compile_valid_raw==1`。错误/警告计数未取得时保留 unknown/null，不伪造0，不用调用前的旧 compile1 代替检查。保留原厂UI、异常和自身持久化语义；需要提示处理时遵循已有授权，不隐藏确认。

最终比较覆盖批准的样式/布局、新资源及新静态控件，精确保全其余可见 getter 业务值、按钮六组按下/释放数组、身份/owner、原状态条件和完整引用图。原生未暴露的字段不得说“全部已回读”；文件侧完整表/BLOB对比与原生 typed 比较互补。若只做保存/检查而未新 Close/Open、模拟或现场通信，分别明确记录，不能外推为全部场景验收通过。

验收分层见[统一验证](unified-validation.md)与[本轮机器验证记录](native-ui-validation.json)：source69/便携89的既有关闭重开证据与本轮source93/94的页面保存、Root85、最终 typed/业务比较分开；本轮没有重新实测所有功能、所有软件或所有版本。技能固化的文件校验/离线编译不增加原生工程验收范围。
