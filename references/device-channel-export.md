# 设备清单、通道导出与量程修改

本文说明如何从已导出的工程读取触摸屏设备清单、按设备导出「设备信息」CSV（格式与 Pro 的导出一致，可导回软件），以及只改「通道处理」列的有界编辑。不涉及外部控制器程序或协议实现。

## 结构

设备窗口归档（`WndDevice` 的 `lbObjects`）实测为三层，不是平表：

```
PLC 节点（节点名 + 短 IP，例如 <节点名> / <a.b>）
  设备（设备名 + 驱动名 + 驱动库路径）
    通道（通道名称 + 变量名 + 属性区）
```

- PLC 节点的识别：字符串形如 `数字.数字` 的短 IP，其前一个字符串为节点名。
- 设备的识别：驱动名字符串所在位置，其前一个字符串为设备名；其后最近的盘符路径为驱动库路径。
- 设备归属到哪个节点：取字节偏移上最近的前一个 PLC 节点。不按界面顺序推断，也不依赖设备数量。

设备内部只有一个通道组，不存在四层结构。

## 命令

```powershell
# 只列设备清单，不写文件
python scripts/native_tool.py channels --export <inspect 导出目录> --list

# 按设备导出 CSV（每个设备一个文件）
python scripts/native_tool.py channels --export <inspect 导出目录> --out <输出目录>

# 只导出其中一个设备
python scripts/native_tool.py channels --export <导出目录> --out <输出目录> --device <设备名>

# 批量改量程：按变量名正则选中，只改「通道处理」列
python scripts/native_tool.py channels-edit --dir <上一步输出目录> --out <新目录> `
  --match '<变量名正则>' --processing '输入:0_10000工程:0_100'

# 或用编辑计划（逐条指定文件 + 变量 + 新值）
python scripts/native_tool.py channels-edit --dir <输出目录> --out <新目录> --plan plan.json
```

`channels` 输出的 `devices.json` 记录设备、PLC 归属、驱动、通道数、未绑定通道数、有通道处理的通道数，以及每个 CSV 的字节数与 SHA。

## 导出格式

与 Pro「设备信息导出」一致，必须严格照此生成，否则导入会失败：

- 编码 GBK，分隔符为**逗号**（不是制表符），换行 CRLF，文件末尾保留 CRLF。
- 前 4 行为设备信息，第 5 行为列标题，其后为数据行：

```
组态设备名称:<设备名>
驱动库文件路径:<盘符:\...\驱动.ui>
驱动构件名称:<驱动名>
驱动构件版本:<驱动构件版本>
通道号,变量名,变量类型,通道名称,读写类型,寄存器名称,数据类型,寄存器地址,地址偏移,通道采集频次,通道处理
```

- `通道号` 从 0 起顺序编号；`地址偏移` 恒为空；`通道采集频次` 恒为 1。
- `变量类型` 由数据类型推导：`通道的第NN位` → `INTEGER`，`ASCII字符串` → `STRING`，其余数值 → `SINGLE`。

## 字段来源与已踩过的坑

| 项目 | 规则 |
| --- | --- |
| 位通道的寄存器地址 | 只写到字节号，位号只出现在「数据类型」列，地址里不重复写位号 |
| `BB` | 8位 **有**符号二进制（不是无符号） |
| `BUB` | 8位 **无**符号二进制 |
| 未绑定变量的通道 | 保留该行，变量名留空，对象编号为 `-1`，`变量类型` 仍按数据类型填 |
| 变量名判定 | 变量名必须紧贴通道名称（间隙为 0），否则判为未绑定 |
| 驱动构件版本 | 工程文件内查不到（驱动 DLL 的文件版本与构件版本无换算关系），按驱动名固定；换机或升级驱动需重新核对 |

`通道处理` 只在属性区出现 `#通道处理` 标记串时才有。两个数值**不固定在某个偏移**：多数通道在变量名之后的固定位置，若属性区夹了一段 `CDevDealMethodXXX` 标识则整体后移。因此按特征定位——两个正浮点相隔 16 字节、中间 12 字节全 0，且值大于 1e-3（滤掉错位读出的非规格化数）。

## 修改通道处理

`channels-edit` 只改第 11 列，并强制校验：

- 每行必须 11 列，列标题与输入完全一致，行数不变。
- 只允许「通道处理」变化，其余 10 列逐字节比对。
- 指定变量在该文件中必须存在且唯一，否则报错退出，不静默跳过。
- 输出写到新目录，输入目录不改。

工具不写数据库。改后的 CSV 由 Pro 的「设备信息导入」写回并保存，这一步属于原厂操作，不能由脚本代替。

## 验证边界

已在 McgsPro 3.3.6.6354 SP1.3 的一个真实工程上核对：多个设备导出的 CSV 与 Pro 的「设备信息导出」**逐字节一致**，覆盖该工程出现的全部通道地址格式（`DBn:STR/WB/WUB/BB/DB`、`I/Q/M` 区、位通道）。比对样本属于用户工程，按仓库样例规则不入库、不在此列名。

其余设备沿用同一规则生成，未逐个与软件导出比对。

已验证：解析、导出字节、仅预期列变化、错误输入被拒绝。
未验证：其他工程家族与驱动版本、其他软件构建、CSV 的逐个设备导入回写、原厂组态检查与现场通信。同格式 CSV 曾在本机由 Pro 导入并保存成功（量程改动在工程内可见），但不等同于全部文件已逐个导入通过。
