# 按当前程序定位 Pro 内部函数

在线准备不再把参考构建的函数地址直接交给 Pro。绑定器读取本次明确选定的 EXE 和相关 DLL，在当前 PE 中定位函数、RTTI 与虚表，生成当前目标的调用资料，再编译业务引擎。软件发行号不参与选择，也没有“必须使用 3.5.1.6963”的要求；该号码仅是旧离线空白模板的来源。

这是函数定位机制的变化，不要求逐个安装或枚举所有历史发行版。参考地址保留为来源索引，不能代替当前解析结果。未执行过的其它安装环境仍不能写成已通过原厂验收。

## 准备和复用

仍使用同一套 Windows、PowerShell 7 和 Python。在线准备增加 `assets/pro-native-bridge/abi-adapter/requirements.txt` 中的 Capstone，用来识别正确的 x86 指令边界。用运行 `run.ps1` 的同一个 Python 安装，不另建一套 Pro 环境。离线编辑及已经准备好的桥的普通请求不要求重新安装或重复执行定位。

`native-doctor` 检查准备依赖；`native-abi` 提供只读定位工具。生产绑定入口默认按当前目标解析并使用派生资料。换了实际程序文件后，重新生成该目标的资料；同一目标不按每个控件重新扫描，也不要求每次重启 Pro。

旧桥可继续传输请求，旧业务 DLL 则不会因为复制新版技能自动变化。记录回执中的 `native_function_binding`、`cross_build_contract`及实际按条目、自动定位和功能隔离能力，不按精确工具修订字符串准入。本次所需能力缺少时，按原连接生成新版业务引擎，再用[已有桥更新命令](pro-native-deployment.md#已有桥的同任务更新)选择，不重建在用 Bootstrap 或清除历史请求。当前分层定位与逐项报告规则见[自动适配](adaptive-native-location.md)。

## 资料和调用的关系

1. 包内参考目录记录函数片段、重定位信息、导出、RTTI 和表槽等识别依据。参考文件的哈希核完整性，不核用户是否安装了作者版本。
2. 定位器按实际模块解析。普通重定位以及相对调用、跳转的操作数与对象字段偏移分别处理，不把任意数字都当成可变地址。函数位置必须有定位证据；匹配不唯一时保留具体缺口。
3. 派生 profile 写入当前地址和可核对的当前字节，绑定器重新计算其文件哈希及引用，保留内容一致性检查。不让 `Hash()` 假装返回参考值，也不删除方法检查。
4. 源码中已确定属于 PE 地址的常量按当前映射生成，包括先存入模板、数组或分支变量的地址；变量 ID、数量、对象字段偏移和其它数据不作全局替换。派生文件中的当前地址不能再映射一次。按序号获取的 DLL 导出也按当前导出表核对，实际序号与原接口的逻辑名称分别处理，不能把 RVA 写成导出序号。
5. 根接口的多函数资料按条目延迟核对。某个未定位的函数在被当前请求使用时报告对应接口，不因无关条目不同而把整套在线功能判成“必须升级”。单项功能依赖未闭合时，仍明确报告该功能的具体缺口。

定位函数不等于证明任意未知对象布局。原有对象类型、字段、参数、工程身份、前像、条件和保存语义继续核对；本次变更不增加 permit、许可文件或版本白名单。

参考目录自含所需的稀疏指令、分支目标与表资料，接收者不需要作者电脑上的参考 EXE/DLL。实际模块与参考来源的完整内容相同时，可以复用已有定位结果；内容不同则执行动态定位。这是缓存等价证明，不是只允许某个哈希或软件版本进入。报告将缓存复用与动态匹配分开记录。

## 报错处理

“函数未定位”“候选不唯一”“RTTI 或表槽未解析”应带实际模块、接口及定位结果。智能体不得把这些报错翻译成“升级到作者版本”。应查看该接口的当前解析资料；已解析的其它功能保持各自状态。

自有源码混装、scope 与 DLL 不一致、准备后目标文件变化、当前工程前像变化分别处理。这些不是软件发行版本限制，也不能用替换参考哈希、清除 claim 或重放超时请求来解决。

文件定位、派生源码编译、连接、原厂业务调用、保存、检查和关闭重开分别记录。自有 PE 地址移动测试只能证明定位算法；不能称为所有旧版 Pro 的实际验收。
