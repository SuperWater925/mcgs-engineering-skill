# 跨机使用与批量执行

## 更新和实际引擎

源码技能、已安装技能、完整包和进程内业务 DLL 是四个不同位置。`turnkey fetch-bundle/setup/prepare-online/install-skill` 用当前技能的源码合同寻找匹配预编译引擎。发布附件 `mcgs-engineering-index.json` 指向小更新；旧完整包只提供可复用的运行时和安装介质，不把当前技能交给旧包脚本执行，也不以安装旧技能解决引擎不匹配。

已有更新目录可作为下一次小更新的文件来源。更新器逐文件核对需要复用的内容，在新目录组装，不要求上一版的 bundle 元数据与最初基底相同。下载或匹配失败给出具体原因，不偷偷回退旧引擎或要求用户重做源码编译。

连接先发现现有 Pro。可用桥继续服务同一 PID、队列和历史回执；需要新版业务 DLL 时在原桥内选择匹配引擎。回执中的实际文件及合同决定正在运行哪个引擎，不能凭技能目录名称判断。实际程序变更后重新物化数据，同文件内容可复用本机定位缓存。

## ABI 按能力使用

- 发行版本、厂商整文件指纹、旧函数实现字节不作为通用准入条件。
- 已唯一识别的具名导出、RTTI 接口角色和调用关系允许内部实现不同；当前函数代码记录用于本次调用一致性，而不是与作者版本逐字匹配。
- 本机 `object_layout` 描述被消费的私有字段；接口地址和字段布局各有来源，不把旧数字套到新对象。未解析的字段只影响依赖它的动作。
- 页面里未修改的未知或外部控件按不透明内容保留，不要求它们先支持新建/复制才能打开整页。
- 目标属性按需求读取；无关字体、组件或保存接口不阻断普通编辑。相同属性值返回无变化，不制造错误。
- 对象身份、目标归属、真实并发变化和超时后的执行状态仍按实际结果处理。这些检查不要求升级 Pro。

## 原生批次与常驻客户端

完整页面施工优先一个 program。默认按同页、操作依赖与消息字节量组织批次，不再默认每 8 项拆分。`--max-merged-actions N` 供需要更细进度的调用者选择。按钮两态合同随属性批次传递；原厂共享条件、动作、绑定保持原义。

原生创建批次建立共享页面基线和对象索引，逐件使用原厂构造、加入和属性接口，按返回结果更新索引；批末统一完整核对、刷新，最后按实际改动页面和模块保存。它不承诺失败时原子回滚。发生失败先读完成前缀，不自动重发已创建对象。

连续独立请求可保持一个客户端：

```powershell
pwsh -NoProfile -File <技能目录>/run.ps1 native-engineering --scope-config <本次scope.json> serve
```

stdin/stdout 使用 JSON Lines。请求包含 `id`、`method`（`inspect`、`execute`、`status`、`stop`），读写请求另含 `project` 和 `specification` 或 `specification_file`。每行返回一个结果，`stop` 只停止客户端，不退出 Pro。复用 Python、连接和 transport 缓存，每个工程请求仍有可关联的持久记录。超时用原 id 的 `status` 核状态，不重新发送同一修改。

## 可选原厂窗口消息通道

`run.ps1 native-hwnd` 提供不依赖内部 ABI 的原厂界面消息入口。菜单命令按当前窗口菜单的完整文字路径解析，不把某个 Pro 构建的命令编号写成通用值。内部 MDI 激活、画布消息、原厂选择集命令、属性编辑和脚本编辑按当前窗口清单定位；不要求全局前台、不最大化。

先 `inventory` 取得当前 PID 的窗口、菜单和控件，再用 `run` 的完整计划连续执行或用 `serve` 保持客户端。该通道依赖具体原厂界面及其实际可用命令，不能把“消息已发送”写成工程检查通过。明确适合的操作可选此通道；内部调用已进入或超时后不自动改走另一通道重复写入。

原厂退出、转换、检查完成等提示可按本轮已有授权，用确切进程、对话框文本和按钮文字响应。无需统一要求电脑操作技能。未识别提示或内容需要新决定时保留现场并报告，不盲选“是”。

## 离线环境与验收

离线选择可用 ACE 位数匹配的工作进程；主入口使用 x64 Python/PowerShell 不意味着 ACE 必须是同一位数。纯在线不要求 ACE。新增控件优先当前工程可中和业务字段的原型，显式克隆才继承原绑定和动作。

验证分别报告文件回读、原厂检查、关闭重开和模拟。性能对比使用同一工程、等量修改和一个 Pro 实例，已有控件编辑与新增页面分别记录；不能用 20 个标签颜色修改推断整页新增速度。各阶段区分客户端墙钟时间与原厂 setter、刷新、保存时间，具体数字以该发布版验证记录为准。
