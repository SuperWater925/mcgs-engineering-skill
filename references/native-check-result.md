# 已打开的原厂组态检查结果

用户或其它已授权流程完成检查后，保持结果对话框打开。将实际进程 ID、编辑器 EXE 和编辑器主窗口句柄传给只读采集器。Stu 和 Pro 使用相同的 Windows 窗口与辅助功能接口。

```powershell
pwsh -NoProfile -File .\run.ps1 native-check-result --pid <进程号> --editor "<实际编辑器EXE>" --main-hwnd <主窗口句柄>
```

存在多个结果对话框时可附加 `--dialog-hwnd <结果窗口句柄>`。采集器核对进程实际文件、可见窗口和属主链。结果保留原始提示文字、控件及窗口身份；可见列表行带有可用的辅助功能身份。列表控件无法读取时保留其身份。未展示在窗口中的行无法从此次采集确定。

成功读取完整中文计数时，退出码为 0，`error_count` 和 `warning_count` 来自原文。若只看到标题、没有结果窗口、发现互相冲突的结果或摘要格式未知，退出码为 2。组态检查记录和编译结果分别验收，已看到检查结果的窗口也需要结合调用方记录的工程身份和本次检查操作判断归属。此命令自身不启动编辑器或执行检查。

## Stu 可核实的范围

已有 Stu 原厂记录覆盖新工程编译、保存、关闭、重开及两次检查，均为零错误、零警告。这里的 `native-check-result` 采集已显示的原厂结果。带 Stu 业务组件的包也可用 [Stu 原生在线入口](stu-native-engineering.md) 主动执行组态检查并读取原厂明细。

在可见的“组态检查列表(双击打开修改)”窗口中，采集器先读取 Windows UI Automation 的行和单元格，未取得行时再通过该控件的 MSAA 客户端对象读取可见行。两次读取须得到相同的行文字和身份。退出码只表示摘要计数状态，明细单独查看。未读到行时保留未知，即使摘要已有警告数。

当计数提示与明细属于两个窗口时，可指定 `--dialog-hwnd <计数提示>`，同时提供 `--details-hwnd <明细顶层窗口>` 和 `--detail-control-hwnd <列表控件>`。分别核实主窗口属主链、列表父子关系、控件身份和稳定行；`selected_details.items` 保留该次可读行。两个窗口是否属于同一次检查、结果是否完整，仍需调用方的工程与操作记录判断。若已关闭计数提示，可单独读取当前明细，计数保持未知。

本地实测 Stu 原厂检查摘要为 0 错误、1 警告。旧采集器在 MSAA 枚举行时无法转换 COM 对象；改用强类型遍历后，读到了警告对象和正文。正文报告测试页动画按钮使用了空图片。计数弹窗与明细分别采集，回执仍独立记录可见行与检查操作关联。

## Pro 原生回执

`project-check-original-root85` 用本次工作函数正常返回 0 且检查后的编译标记为 1 判断 `native_check_passed`。失败后先读取当次原厂根诊断及 `diagnostics_unavailable_reason`。工作函数提前返回时，其报告对象可能缺少本次完整列表，计数保持未知。

当适配器能核对报告对象、当次已完成检查和完整行表时，`original_diagnostic_report` 提供原厂错误和警告计数以及逐行内容。此时 `error_warning_counts_known` 和 `all_error_warning_records_covered` 均为真。该证据与保存、文件回读、关闭重开和本机模拟分别记录。
